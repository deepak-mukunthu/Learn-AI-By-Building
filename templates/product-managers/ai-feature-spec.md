# One-page spec for an AI feature

| | |
| --- | --- |
| **The job** (one sentence, as a user would say it) | |
| **Who uses it, and what they do today** | |
| **A good answer looks like** (three real examples) | |
| **A bad answer looks like** (three examples, ranked by harm) | |
| **Quality bar to launch** (for example, 90% of the test set, and zero failures in the "must never" group) | |
| **Failure budget** (how many bad answers per 1,000 we accept, and where a person catches them) | |
| **Handoff to a person** (when, to whom, with what context) | |
| **Data it may use** (sources, owners, how fresh) | |
| **Actions it may take** (alone, with approval, never) | |
| **Cost ceiling** (per conversation, per month) | |
| **How we'll know it's better next month** (the three numbers we track) | |

The two rows that differ from an ordinary spec are the quality bar and the failure budget. Without them, "ship it" and "it's not ready" turn into arguments of opinion.
